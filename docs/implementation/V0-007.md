# V0-007 — Blocks

Date: 2026-10-02.

A Block is time the user has deliberately chosen a purpose for. This tranche stores that truth and the smallest way to add, inspect, edit, and remove it.

Protected Time remains a different fact: time made unavailable for allocation. A Block does not release that, and Protected Time does not create a Block.

## Representation

`blocks` is its own table. It is not Protected Time, a Task, a Work shift, a Commitment, or a generic event.

Purpose is required. Blank text is rejected. The stored text is trimmed and at most 80 characters. It is not chosen from a list.

`context_id` is optional. It references the user's own Context through the same owner pair Tasks already use. Deleting that Context clears the reference and leaves the Block and its purpose. The Context name is not copied into the purpose.

An all-day row stores the civil date and null clock times. A timed row stores local start and end on that date. The confirmed zone on `temporal_settings` interprets those times. It is not copied onto the row, so a later confirmed-zone change reinterprets existing local times. This tranche does not store a zone per Block.

If the end is earlier than or equal to the start, the Block continues into the next civil date. It does not cover further days. Equal times use that overnight reading.

There is no recurrence, no Task link, and no join table.

## Independence

Saving a Block does not write Protected Time, Tasks, Today, the Work schedule, or the Active Thread. Removing a Block removes only that row. Overlap with Protected Time, a Work shift, another Block, or a Task planned today is allowed and not treated as a conflict.

A Commitment is still fixed or external time. It is not stored here.

## Confirmed time zone and daylight saving

A Block is not saved from a browser guess. Without a confirmed zone, Schedule says so and does not open the form. The existing confirmation control remains the path.

A local time that does not occur is not given a substitute instant, and that row is not described as containing the current time. A local time that occurs twice stays stored as that local time and uses the existing first round-trip.

## Projection

`projectBlocks` takes stored Blocks, a supplied instant, and the confirmed zone. It does not read Protected Time, a clock, the network, or the database.

An all-day Block is current on its civil date. A timed Block is current from its start until, and not including, its end. The Schedule list shows current, upcoming, and unresolved rows in civil order. Past rows stay stored and are not shown. The order is chronological, not a rank. The list can say the current time is inside a row. It does not calculate capacity, free time, overlap, or a Timeline.

## Schedule

Blocks sit under Protected Time on `/schedule`. The bottom bar is still Tasks and Schedule. Add block stays closed until opened. The form asks for a date, all day or timed, start and end when timed, an optional Context, and a purpose. Start and end reuse the 12-hour selects. Edit uses the same fields. Remove asks once on the row.

An open form that has not been saved is local. Cancel drops it. Leaving Schedule drops it. Protected Time's unsaved form behaves as it did in V0-006.

## What did not change

Task, Today, Must Do, Due, Active Thread, Resume, Work schedule, Protected Time, and the confirmed time zone are unchanged. No Task column changed.

Commitments, Timeline, temporal composition, capacity, availability calculations, Task and Block associations, recurring Blocks, recurring obligations, NOW, `rankNow`, Task ranking, Notes, reminders, Pulse, notifications, Google Calendar, voice, a watch app, a service worker, AI, LLMs, machine learning, agents, and a visual redesign were not added.

## Tests

Domain tests cover a required purpose, optional Context, minute fidelity, and the overnight comparison. Projection tests cover order, the Boise/UTC boundary, half-open bounds, overnight containment, a missing local hour, and an ambiguous `01:30`. Persistence tests cover the write shape, a failed write, owner policies, and the same-owner Context reference. The Schedule markup covers the list, the editor, removal, 12:00 AM and 12:00 PM, and the unchanged bottom bar.
