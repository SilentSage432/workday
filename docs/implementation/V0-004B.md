# V0-004B — mobile interaction foundation

Date: 2026-10-02.

Real use after V0-004A showed four interaction problems: Capture could be open after a return from the schedule, Android's clock-face time picker fought repeated shift entry, each day asked for its own Save, and the two primary surfaces had no persistent navigation. This tranche changes those mechanics. It does not change what a Task, a shift, or a Work day means.

## Capture

The Capture session already lived above the tasks view. No schedule function set it open. The tasks view, including Capture, was unmounted while the schedule was on screen and mounted again on the way back. The control that left the schedule was removed in that same update. On a phone, that is how a tap can land on whatever replaces it. The first large action in the tasks view is Capture. After `openCapture` ran, the open flag stayed in the parent, so the editor was still there.

The repair does not clear Capture on every return. That would throw away an editor the user had actually opened, and a draft they had not saved.

Capture now lives in the signed-in frame. It starts closed. The schedule route does not read or write it. Tasks and Schedule are separate routes, and the bottom navigation link that moves between them stays mounted, so the tap is not handed to a control that just appeared. A meaningful draft still survives that trip. If Capture was closed, it stays closed and the draft is only the quiet line under the Capture button. The editor opens from that button, or stays open after a failed save. A successful save still clears the draft, closes the editor, and does not touch the Active Thread. A refresh still drops the draft.

## Direct time entry

Work schedule editing no longer uses `<input type="time">`. Each start and end is three selects: hour, minute, and AM/PM. The stored value is still `HH:MM`. Conversion is deterministic, including 12:00 AM, 12:00 PM, 6:00 AM, 2:30 PM, and 11:45 PM. Every minute from 00 through 59 is available, so a stored minute such as 07 is not rounded. An end that is earlier than or equal to the start still means the shift continues after midnight, and that sentence still appears.

## Edit week

Edit week copies the visible Saturday–Friday week into a local draft. Off, unknown, and scheduled shifts can all change in that draft. Nothing is written until Save week. Cancel throws the draft away and writes nothing. Save week sends only the days that differ from the loaded week. An incomplete shift is refused before any write, and the editor stays open.

If the user changes weeks, leaves for Tasks, or edits the time zone while the draft differs from the loaded week, the page asks them to save, discard, or stay. That choice is in the page. It is not only the browser's unload prompt.

## Atomicity

Several independent row writes can succeed partway and then fail. Cancel could not undo that, and a later error could not honestly say the week was unchanged. `save_work_week` is one transaction for the signed-in user and the seven dates of the week that was on screen. It inserts, updates, or deletes only those changed days, under the existing row rules and row level security. The browser calls it once. If it returns an error, the editor stays open and the page does not say the week was saved. If there is nothing to change, it does not call the database. The migration is `20261003001500_save_work_week.sql`.

## Navigation

The signed-in bottom bar has Tasks and Schedule, each with a Lucide icon and a word. Tasks is `/`. Schedule is `/schedule`. Refresh and the browser's back and forward buttons follow those routes. The bar stays at the bottom, including the safe area, and the page padding clears it. The same bar is used on a wide screen. There is no NOW item.

## Icons

Lucide is the icon vocabulary. The record is [../decisions/2026-10-02-icon-vocabulary.md](../decisions/2026-10-02-icon-vocabulary.md). The plus sign on Capture is now the Plus icon plus the word Capture. Previous and Next keep their words and gain chevrons. Change keeps its word and gains a pencil. The em dash for a day with no row stays a fact.

## What did not change

Task, Context, Must do, Planned, Due, Active Thread, Resume, Off versus unknown, Opening / Mid / Closing, the confirmed time zone, the Saturday-first week, Work orientation, Power Hour, and the FSR boundary are unchanged. No projection file was edited.

## Tests

Tests cover the closed Capture button, a preserved draft that does not open the editor, a successful save returning to closed, the schedule route not calling `openCapture`, 12-hour conversion, minute fidelity, the week draft and its diff, a failed week save, the absence of `<input type="time">`, one Save week action, and the Tasks and Schedule destinations.

## Exclusions

Today, NOW, `rankNow`, Task ranking, recurring obligations, Notes, Blocks, Commitments, Timeline, reminders, Pulse, Google Calendar, notifications, voice, a service worker, AI, LLMs, machine learning, and agents were not added.
