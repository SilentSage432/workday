# V0-012A — Temporal selection refinement and contextual handoff

Date: 2026-10-03.

Grab time, refine time, then establish the intended meaning.

This tranche does not collect the fields that would establish a fact, and it does not persist anything.

## What was verified first

`main` was clean at `4d7f7c7d2c9b646ccfaba20e48091650ec1cb6a9`, matching `origin/main`. The seven migrations from `20261002213000` through `20261003040000` were unchanged. A second selection, a stored meaning, or a Timeline write was not required.

## Phone evidence

The V0-012 chooser felt like something had just shown up above the calendar. The expected sequence is to select time in the canvas, release, and continue there: see the selected territory, refine it if needed, and say what it means.

The selected region also felt like it should stay manipulable. The specific instinct was to grab the bottom edge and change the end. That is recorded for a later tranche. Resize handles are not in this one. Precise start and end controls are the refinement that can be tried before edge gestures are designed against scrolling and selection.

Gesture provides speed. Precise controls provide accuracy. That is evidence about this interaction, not a domain rule.

## Where it lives

After the gesture settles, `DayCanvas` opens a surface over the visible day, inside the canvas frame. It is not a toast, not a fixed viewport layer, and not another section above the axis. The band stays on the axis. The surface shows the same range, then the controls, then the meaning question.

The selection value is still the civil date and the local minutes. `refine` writes those minutes when the order is valid. An invalid attempt stays in the controls and leaves the band alone. It is not sorted into a valid range, and it is not a second selection.

## Precision

The gesture still snaps to 15 minutes, with the same 220ms hold, 10px slop, visible-scrollport clamp, and no auto-scroll.

Stored Work, Protected Time, Block, and Commitment local times are `HH:MM`, including minutes that are not multiples of 15. The surface reuses the existing hour, minute, and AM/PM fields, so a refined selection can use any minute. The minimum accepted range is one minute, inside this civil day. "End of this civil day" sets the end to the next midnight, because 12:00 AM is already the start.

A new gesture still clears the intended meaning. Refining the current range keeps it. Change meaning still clears only the meaning. Clear still removes the range, the meaning, and the surface.

A press inside the current band does not start a replacement selection. A press outside it can.

## DST and facts

A refined range that includes a spring-forward gap still says that part of the local clock range does not occur. A refined range inside the repeated fall-back hour still says that part of it occurs twice. No instant is chosen.

The question stays available over Work, Protected Time, a Block, a Commitment, or several of those. Nothing is disabled, and nothing is called available or a conflict.

Manage schedule is unchanged. Opening it, changing day, refreshing source truth, or changing the confirmed time zone still clears the session.

## Left alone

No migration. No production rows. No purpose, title, label, or Context field. No resize handle. No dependency.

## Limits noticed while building

The surface is centered in the visible canvas, which is the field the release continues into. The card is tall enough, once both times and the three actions are showing, that it can cover most of that field. The band remains behind it, and the written range is in the card. Whether that feels tied to the selected territory is still a phone question. Grabbing the bottom edge is the next direct-manipulation hypothesis, not this implementation.

The hour and minute fields are understandable as the same controls used elsewhere, and they are more steps than a drag. That is the accuracy side of the evidence above.

## Next question

After this surface has been used on a phone: what is the minimum meaning-specific information required before the user can explicitly establish each kind of temporal truth?

Protected Time may need only the range; its optional label has to be inspected first. A Block requires a purpose, and Context may be optional. A Commitment requires a title. Those fields are not here.
