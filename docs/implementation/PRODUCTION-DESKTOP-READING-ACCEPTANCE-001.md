# PRODUCTION-DESKTOP-READING-ACCEPTANCE-001 — desktop temporal reading

Physical inspection accepted desktop Present and desktop Day. This tranche promotes that reading to production `/` and retires the temporary inspection route.

## Production seam

`/` is one instrument.

- Below 960px, the accepted phone continuity remains. A fresh phone entry is still Day.
- At 960px and wider, Present and Day use the accepted desktop reading. Exact time still opens the existing day clock.

There is no second product path and no composition flag. `/desktop-reading` was the inspection route for the candidate. That route is retired. `/instrument` remains historical experimental evidence and is not promoted.

## Present

Desktop Present asks where the person is now.

Authoritative Now owns the composition. The civil date supports it. The reading shows only established truth that contains that Now, then the Active Thread, then quiet Exact time. There is no whole-day inscription.

## Day

Desktop Day asks where the person is in the selected civil day.

The selected civil date owns the composition. Quiet Now appears only when that day is authoritative today. The reading shows established truth for that civil day, then the Active Thread, then one inscription from 00:00 to 24:00.

The inscription is one dimension. Established spans stay proportional to civil time, in the existing hues, and overlaps share the line. The references are 12:00 AM, 6:00 AM, 12:00 PM, and 6:00 PM. The neutral baseline is the physically accepted 2px stroke. Now is a warm-gold reference inside the inscription only when the selected day is today. Exact time sits beneath the inscription. Unmarked time stays unmarked and does not imply availability. Desktop Day does not label Work Off. Phone Day, Week, Month, and the Exact time clock still may.

## Week, Month, and Direction

Week remains the shared seven-column temporal landscape. Desktop Week is physically accepted in [DESKTOP-WEEK-ACCEPTANCE-001.md](DESKTOP-WEEK-ACCEPTANCE-001.md). Month remains the shared 7×4 landscape. Direction remains the leading Month column. Legitimate Work Off representation stays where it was already established. Desktop Month is physically accepted in [DESKTOP-MONTH-ACCEPTANCE-001.md](DESKTOP-MONTH-ACCEPTANCE-001.md).

## Drawer

Desktop uses one `surface` state. The surface is a borrowed right-side drawer. The reading stays mounted and perceivable. The drawer is non-modal. Escape closes it. Focus moves to the dialog and returns to the invoking control. Capture does not become permanent navigation. There is no standing 22rem production rail. Work schedule management is an accepted operation on this surface. [WORK-SCHEDULE-AUTHORITY-PATH-ACCEPTANCE-001.md](WORK-SCHEDULE-AUTHORITY-PATH-ACCEPTANCE-001.md).

## Auth

[AUTH-BOOTSTRAP-RELIABILITY-001.md](AUTH-BOOTSTRAP-RELIABILITY-001.md) remains in force. The subscription is established before `getSession()`. `INITIAL_SESSION` is ignored. A newer auth event wins over a stale pending read. A successful null session shows the signed-out form. A successful session shows signed-in children. A failed read stays a failed check, with retry. Cleanup ignores a stale read and removes the subscription. The repair does not clear storage and does not sign the user out. `127.0.0.1` remains an allowed development origin.

## Day anchor

Current anchor behavior is unchanged. The instrument still initializes an unset anchor from the live civil date in the active zone, and it still keeps that value until an explicit move.

The diagnostic in [ORIENT-DESKTOP-DAY-INSCRIPTION-002.md](ORIENT-DESKTOP-DAY-INSCRIPTION-002.md) distinguishes an implicit temporal anchor from an explicit human-established anchor. That distinction is examined in [DAY-ANCHOR-PROVENANCE-DISCOVERY-001.md](DAY-ANCHOR-PROVENANCE-DISCOVERY-001.md) and recorded, without a midnight change, in [DAY-ANCHOR-PROVENANCE-001.md](DAY-ANCHOR-PROVENANCE-001.md). There is no provenance, no midnight movement, and no persistence added here.
