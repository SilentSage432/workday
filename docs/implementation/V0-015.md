# V0-015 — Established fact lifecycle

Date: 2026-10-03.

Baseline: `a8ad6afaf5066206f9ba8b385752f762f405001e` on `main` (V0-014).

## Phone evidence

V0-014 was used on Samsung/Chrome. A tap on the existing striped Protected Time referred to that fact, showed the read-only surface, and showed its existing 4:45 PM–5:00 PM bounds. It did not create a temporal selection underneath the fact.

The immediate reaction was that the fact could be selected, and that was all. Fact reference is the way in. It is not a usable lifecycle by itself.

Edit and delete in this tranche have not yet been accepted on that phone.

## What this adds

A referenced Protected Time, Block, or Commitment can be edited or deleted. Work still shows its shift and range, with Close only.

Edit opens the existing fact. The draft starts from the stored start, end, and label, purpose, or title. Context is included for a Block when the day already has contexts. The kind does not change. The civil date of the fact does not change. A Commitment update still goes through the existing definition, which keeps `user_created`.

The time controls are the same steppers already used for a new temporal selection: hour, minute, and AM/PM. There is no native time select, no drag-to-move, and no resize handle.

Save is the write. Until Save, the stored fact is unchanged. Save calls the existing update for that table, matched to the existing id and the signed-in user. It does not insert a replacement. After a successful Save, the day reloads through the same remount used for establishment, and the editor closes. If the write fails, the draft and the editor stay, and the failure is shown.

Delete first asks: "Delete this Protected Time?", "Delete this Block?", or "Delete this Commitment?". Cancel leaves the fact. Confirm calls the existing delete for that id and user. Success reloads the day and clears the reference. Failure leaves the fact and says so. There is no undo.

Overlap is unchanged. An edit may occupy time that already holds another fact. There is no conflict, capacity, or availability behavior, and no ranking.

## Reachability

The articles are still not the pointer target. A short tap still refers to the fact. A hold that begins on a fact still refers to the time, including while an edit is open: that hold leaves the edit and selects time. Movement past the slop before the hold still scrolls.

## Persistence

`updateProtectedTime`, `updateBlock`, `updateCommitment`, `deleteProtectedTime`, `deleteBlock`, and `deleteCommitment` were already the owned write paths. Each update and delete filters on the row id and `user_id`. Row level security for those statements was already in the existing migrations. No schema change was required.

## Tests

Canvas tests cover Edit and Delete on each user-created kind, the loaded draft, a change that waits for Save, an update of the same id, a failed Save that keeps the draft, delete confirmation, cancel, a successful delete, and a failed delete. Work has no Edit or Delete. A hold that begins during an edit still selects time.

happy-dom does not prove what a finger hits in Chrome. The phone procedure below is the acceptance authority.

## Phone acceptance

On Samsung/Chrome, after this build is deployed:

A. Tap the existing Protected Time. The fact is selected.

B. Tap Edit. The existing 4:45 PM–5:00 PM values appear.

C. Change the end to 5:15 PM and Save. The editor closes. The same Protected Time renders 4:45 PM–5:15 PM.

D. Reload. 4:45 PM–5:15 PM is still there.

E. Select it again. Edit and Delete are available.

F. Enter Delete. A confirmation appears.

G. Cancel. The fact remains.

H. Repeat Delete and confirm. The fact disappears.

I. Reload. The fact stays deleted.

J. Create another Protected Time. Establishment still works.

K. Hold, then drag, through an existing fact. Temporal selection still works.

L. Start a scroll on an existing fact. The canvas scrolls.

## Unchanged

No new domain primitive, no Timeline semantic change, no schema or migration, no RLS change, no drag, and no resize. Work's own lifecycle remains for a later tranche.
