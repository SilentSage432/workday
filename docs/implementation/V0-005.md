# V0-005 — intentional Today planning

Date: 2026-10-02.

Today means this Task is deliberately planned for the user's current civil day. This tranche teaches that relationship and gives a direct way to set or clear it. It does not add a stored Today state.

## Projection

`projectTodayTasks` returns the open Tasks whose `plannedOn` equals a supplied civil date. It keeps the order it was given, which is creation order from the existing open-Task query. That order is not priority.

The projection does not read the clock, the network, or Supabase. The Tasks page supplies the civil date from `new Date()` and the confirmed IANA zone, using the existing `civilDateInTimeZone` function. The date is not taken from UTC and not from the server's local calendar. A task planned for 2026-10-02 is Today in America/Boise at 2026-10-03T05:30:00Z, and it is not Today in UTC at that same instant.

Due today, Must Do, Active Thread, and creation on this civil day do not qualify. A completed Task does not appear, even when `planned_on` is still this date.

## No confirmed time zone

A browser suggestion is not confirmed temporal truth. If `temporal_settings` has no row, Today says that a confirmed time zone is required and links to Schedule, which already owns that confirmation. Plan for Today and Move to Today are not offered. Existing planned and due dates on open Tasks still render as stored facts.

If the settings row cannot be loaded, Today says so and does not guess a zone. A failure to load the Work schedule does not discard a zone that did load, so Today can still use it.

## Interactions

Plan for Today sets `planned_on` to the current civil date. Move to Today is the same write when the Task already has a different planned date, and the button says so. Remove from Today sets `planned_on` to null. Each write sends only that column through the existing Task update. Due, Must Do, Context, title, origin, completion, and the Active Thread stay as they were.

Capture can still set a planned date directly. That remains the same field.

A failed update says the planned day is unchanged. The page does not replace the Task until the update returns.

## Completion

Completion still writes only `completed_at`. It does not clear `planned_on`. The Task leaves the open Today projection because it is no longer open. If it was the Active Thread, the existing completion trigger still clears that thread.

## Surface

Today sits on the Tasks route, after Resume and Work orientation, and before Capture and the broader open list. It is not a bottom-bar destination. There is no NOW item.

The list shows title, Context when assigned, Must Do when set, and Due when set. It does not repeat the planned date under a heading that is already that day. It does not show a score, a rank, or a time of day.

When the Active Thread is also planned Today, Resume keeps the full card. The Today row names it as the current thread and offers Remove from Today. It does not repeat Leave thread or a second Complete.

Other Today Tasks stay out of the open-Task list so the same card is not drawn twice. They remain open Tasks in the loaded set, and Start and Complete stay on the Today row. The open list says when every open Task is already planned today. A future planned date stays on the open list with Move to Today, next to its Planned fact, so the previous date is visible.

## What did not change

Task, Context, Must Do, Due, Active Thread, Resume, Work schedule, Off versus unknown, Opening / Mid / Closing, the confirmed time zone, the Work fiscal week, Work orientation, and the Power Hour and FSR facts are unchanged.

No migration was added. Hosted migration history still matches the four existing files. This tranche did not write the account's Tasks, thread, Contexts, zone, or schedule rows.

Protected Time, Blocks, Commitments, Timeline, capacity, NOW, `rankNow`, Task ranking, recurring obligations, Notes, reminders, Pulse, notifications, Google Calendar, voice, a service worker, AI, LLMs, machine learning, and agents were not added.
