# V0-013 — Establish selected temporal truth

Date: 2026-10-03.

Baseline: `e86f9cff3e9574059ed99d8d8a113eb8b20bfde5` on `main`, matching `origin/main`.

Grab time, refine time, name the intended meaning, provide the minimum information for that meaning, then explicitly establish the truth.

## Authority

Nothing is persisted because a range was selected, a meaning was chosen, or fields were filled in. The explicit Save is the authority boundary. Save is the verb already used by the Manage schedule forms for Protected Time, Blocks, and Commitments. It is not a domain primitive.

`canvasEstablishment.ts` builds the existing timed input. `WorkSchedule` writes it through `createProtectedTime`, `createBlock`, or `createCommitment`, then calls the existing `noteCanvasReload`. That remounts the day canvas, so the surface closes and the reloaded day can show the new fact. There is no second Done and no success modal.

If the write fails, the surface, the selection, the meaning, and the draft stay. The error is a factual alert. Save can be tried again.

## What was verified first

The working tree was clean at the baseline. The migrations from `20261002213000` through `20261003040000` were unchanged. No migration was added.

Protected Time stores a timed or all-day interval. `label` is nullable. A blank label becomes null. A Block stores a required `purpose` and an optional `context_id`. A Commitment stores a required `title` and origin `user_created`. Each table's row-level security allows the signed-in user to insert their own rows. Timed rows store `start_local` and `end_local`. The zone lives on temporal settings, not on the row. Those columns already accept a range chosen on the canvas, so no new table or column was required.

The create functions insert local text as `HH:MM:00`. That trailing `:00` is the database `time` representation. It is not a user-facing seconds field. They do not convert the local time to an instant.

## Minimum fields

Protected Time: the selected range. Label is optional, visually secondary, and not required.

Block: purpose, required, at most 80 characters. Context is a select only when the user already has Contexts. None is the default. The helper says it does not replace the purpose. An empty Context is stored as null. It is not inferred. No Task is created.

Commitment: title, required, at most 80 characters. Nothing else is asked.

## Completion

The surface stays in place: selected time, the meaning question, then the fields for the chosen meaning, then Save. While Saving, the button says Saving.

The draft lives in the day-canvas session, not in the surface that remounts when the minutes change. Refining the start or end keeps the purpose, title, or optional label. Changing the meaning, or starting a new gesture, clears the draft that no longer applies. A Block purpose does not become a Commitment title.

Save is disabled when the range draft is invalid, when a Block has no purpose, when a Commitment has no title, or when the local clock range is unresolved. An ordinary range can be saved.

## Dismissal

Close, labeled "Close selected time", Clear, and a completed tap outside the surface all abandon the unsaved interaction. They clear the selection, the intended meaning, and the draft, and they persist nothing. Clear and Close are redundant at the state level. Clear stays because it was already understood. Close is the compact control. They are not two different persistence operations.

A mouse or pen press outside the band does not select until the pointer moves more than 10 pixels. Releasing inside that slop abandons. A larger move starts a new selection and clears the previous meaning, which is the existing replacement gesture.

A touch that moves past the slop before the hold remains a scroll and does not abandon. A touch that releases while still pending, outside the band, abandons. A press inside the current band still does nothing. The hold, the slop, the 15-minute snap, and the refusal to scroll the canvas automatically are unchanged.

## Time controls

V0-012A reused the shared hour, minute, and AM/PM selects. There is no `type="time"` and no seconds field. On a phone, activating a select opens the native picker immediately. The minute select has sixty values, which matches the report of landing in an overly granular slot. The canvas now shows the hour, minute, and AM/PM as text, with earlier and later buttons for the hour and the minute, and a button that toggles AM/PM. Those controls do not open a picker or the keyboard. Manage schedule still uses the shared selects. Stored precision is still the minute. The gesture still snaps to 15 minutes.

The steppers were not exercised on the user's phone in this tranche. The native minute wheel is no longer on the canvas. Repeated taps are the remaining way to move many minutes.

## Overlap and existing facts

A new fact can be saved over Work, Protected Time, a Block, and a Commitment. Save is not disabled for overlap. There is no conflict warning, winner, capacity, or availability calculation.

The canvas still does not edit, move, resize, or delete an existing fact. Resize handles are not added. The bottom-edge instinct from V0-012A remains evidence for a later tranche.

## DST

If any minute in the selected range does not occur, or occurs twice, the surface says so and Save stays unavailable. The sentence is "Save stays unavailable for this local clock range." The write is not called, so no instant is fabricated and no fall-back occurrence is selected. An ordinary hour on a spring-forward or fall-back civil day can still be saved. No new DST policy is decided here.

## Tests

The canvas tests cover the minimum fields, the absence of a write before Save, success that clears the transient state by the existing discard token, a failed write that keeps the draft, Close, Clear, and an outside tap, a scroll that does not abandon, refinement that keeps the draft, a meaning change that drops the other kind's fields, overlap, and unresolved spring-forward and fall-back ranges.

Authenticated browser validation was not available. The schedule page asks for a sign-in, and this tranche does not request credentials or weaken that gate. No production row was created.
