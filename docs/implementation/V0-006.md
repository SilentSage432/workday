# V0-006 — Protected Time

Date: 2026-10-02.

Protected Time is time the user has deliberately made unavailable for allocation. Protected does not mean occupied. This tranche stores that truth and the smallest way to add, inspect, edit, and remove it.

Availability is established, not assumed. Unscheduled time must not automatically be interpreted as allocatable time. This tranche establishes only the Protected Time side of that model. It does not decide that any other hour is free.

## Representation

`protected_time` is its own table. It is not a Work day, a Task, a Block, or a Commitment, and it is not a generic event table.

An all-day row stores the civil date and nothing else about the clock. It is not saved as 00:00–23:59. A civil date is not assumed to be a 24-hour instant interval, because a daylight-saving day is not.

A timed row stores that civil date plus a local start and local end, as `HH:MM`. The confirmed IANA zone on `temporal_settings` interprets those times when a projection needs an instant. The zone is not copied onto the row, which is the same choice the Work schedule already makes. If the user later confirms a different zone, existing local times are read in the new zone.

If the end is earlier than or equal to the start, the interval continues into the next civil date. That is the same local comparison the Work shift uses. It is not stored as a second date, and it is not a multi-day span beyond that next date. Equal times are that overnight reading, not a zero-length interval.

A label is optional. Blank text is stored as null. There is no enum for family, time off, or unavailable. There is no `context_id`. There is no recurrence. There is no origin column: saving the row is the user establishing it.

Two rows may overlap, including a Work shift or a Task planned for the same day. The product does not merge them and does not move the Task.

## Confirmed time zone

Protected Time is not saved from a browser guess. If no zone is confirmed, the Schedule section says so and does not open the form. The existing time-zone confirmation on that page remains the path. This tranche does not add a profile and does not change auth. Hosted public signup stays as the operator left it.

## Daylight saving

Storage keeps the civil date and the local times. It does not collapse them to an instant at write time.

When a projection needs bounds, it uses the existing zone conversion. A local time that does not occur, such as 2:30 AM on the spring-forward day, is not given a substitute instant. That row stays on the current/upcoming list without a claim that the current time is inside it. A local time that occurs twice, such as 1:30 AM on the fall-back day, still uses the existing first round-trip. The stored value remains `01:30`.

## Projection

`projectProtectedTime` takes the stored rows, a supplied instant, and the confirmed zone. It does not read a clock, the network, or the database.

An all-day row is current on its civil date, upcoming after that, and past before that. A timed row is current from its start instant until, and not including, its end instant. The default Schedule list is current, upcoming, and any timed row whose bounds cannot be resolved and might still be in range. Past rows stay in the table and are not shown. Order is the civil start, then all-day before a timed row at the same start, then creation time. That order is chronological. It is not a rank, and it is not capacity.

The list can say that the current time is inside a row. Tasks and Home do not change because of that.

## Schedule

Protected time sits on the Schedule route, under the Work week. The bottom bar is still Tasks and Schedule. Work Off is unchanged and does not create a row.

Add protected time stays closed until the user opens it. The form asks for a date, all day or timed, a start and end when timed, and an optional label. Start and end reuse the 12-hour selects. There is no `<input type="time">`. Edit uses the same fields. Remove asks once, on the row, and then deletes only that row.

An open form that has not been saved is local. Leaving Schedule drops it. Cancel does the same without leaving.

## What did not change

Task, Today, Must Do, Due, Active Thread, Resume, Work schedule, Off versus unknown, and the confirmed time zone are unchanged. No Task column changed.

Blocks, Commitments, Timeline, capacity, availability calculations, NOW, `rankNow`, Task ranking, recurring Protected Time, recurring obligations, Notes, reminders, Pulse, notifications, Google Calendar, voice, a watch app, a service worker, AI, LLMs, machine learning, and agents were not added.

## Tests

Domain tests cover all-day civil truth, timed local times, minute fidelity, the overnight comparison, a blank label, and the absence of Context, recurrence, and a clock. Projection tests cover order, the Boise/UTC boundary, half-open timed bounds, overnight containment, a missing local hour, and an ambiguous local time that stays `01:30`. Persistence tests cover the write shape and the migration's owner-only policies. The Schedule markup covers the list, the editor, removal, the confirmed-zone requirement, and the unchanged bottom bar.
