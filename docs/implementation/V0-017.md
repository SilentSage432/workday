# V0-017 — Quick capture

Date: 2026-10-03.

Baseline: `9f06952215615f1287c3713a85efac6737d2e9f7` on `main` (V0-016).

## What this adds

The signed-in Tasks screen and the Schedule screen both show a title field without a first tap on Capture. Save creates a normal Task through `newTaskFromCapture` and `createTask`.

A blank or whitespace title is refused. A real title is trimmed. Unless the user opens More options and sets them, Context, planned day, and due day stay null, and Must Do stays false. Origin stays `user_created`. The new Task is open.

The Active Thread is not written. Today does not gain the Task unless the user set a planned day. Current temporal orientation is not an input. No Block, Commitment, or Protected Time is created.

The draft lives in the signed-in shell, so it survives Tasks to Schedule and the reverse during one browser session. It is not stored for a reload.

Success clears the draft and leaves the field open. The title is focused again so another thought can be typed without reopening the control. Failure leaves the draft and the error, and Save can be used again. A second submit while a save is in flight returns without another insert. The field is disabled during that save.

Enter in the title field submits the form. This record does not claim a desktop test proves the phone keyboard.

Schedule does not navigate to Tasks, change the selected day, or start a temporal selection because a Task was captured.

## Unchanged

No schema. No Note. No voice, microphone, grammar, or model runtime. No reminder, notification, or service worker. No Task edit, delete, or reopen. The optional fields are the ones Capture already had.
